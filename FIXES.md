# Bug fix log — Gutok Drive

1. **package.json**: dependency `"20": "^3.1.9"` bukan package asli, bikin `npm install`/`npm ci` gagal. Dihapus, diganti `engines.node: >=20`. `package-lock.json` sudah di-regenerate biar sinkron.
2. **assets/styles.css**: logo minta `/image/logo.jpg` yang gak pernah ada (file aslinya di root assets). Diganti `/logo.jpg` → logo tampil.
3. **ecosystem.config.cjs**: `STORAGE_CONFIG_KEY` dan `MAX_FILE_SIZE` gak ada di `env`. PM2 pakai env dari file ini secara eksklusif saat start/restart — kalau sebelumnya kamu jalanin `npm start` manual pakai secret custom lalu pindah ke PM2, key balik ke default dan **semua config provider yang udah terenkripsi jadi gak bisa didekrip lagi**. Sudah ditambahkan, WAJIB kamu isi manual dengan secret yang sama persis dengan yang dipakai saat setup pertama kali.
4. **.env.example**: `STORAGE_CONFIG_KEY` gak ada padahal README bilang wajib. Ditambahkan.
5. **server.js** (`getGoogleAccessToken`): ada jalur lama yang reuse token OAuth mentah dari config selamanya tanpa refresh. Token Google expired ~1 jam → upload Google Drive gagal berkala tanpa pesan jelas. Jalur ini dihapus, sekarang selalu generate token baru dari service account JSON (auto-refresh tiap request, sesuai desain awal).
6. **assets/app.js** (form "Tambah storage" → Google Drive): sebelumnya minta field "Google access token" yang gak pernah bisa diisi user secara valid dan gak dipakai validasi backend (backend butuh `serviceAccountJson`). Diganti jadi textarea Service Account JSON, jadi provider Google Drive bisa langsung dikonfigurasi sekali jalan (gak perlu buat lalu edit lagi).
7. **Target Cloudflare Workers dihapus**: `src/worker.js`, `wrangler.toml`, dan `migrations/0001_init.sql` dihapus karena aplikasi hanya di-deploy di VPS. Worker itu memang masih Fase 1 (tanpa share link, folder delete, CDN slug, retention, enkripsi), dan skema di migrasi D1-nya sudah menyimpang dari skema asli `server.js` (tanpa tabel `sessions`, tanpa kolom `encrypted`, `retention_type`, `retention_value`, `expires_at`, `config_json`) sehingga kalau dijalankan database yang terbentuk tidak bisa dipakai login/upload. Sekarang targetnya satu saja: `server.js` + SQLite + PM2, dan skema dibuat otomatis saat aplikasi start.
8. **server.js** (`PATCH /api/admin/providers/:id`): request yang cuma mengirim `config` tetap menjalankan `UPDATE providers SET enabled = ...`, jadi provider yang sedang aktif mati sendiri setiap kali kredensialnya di-edit. Sekarang status aktif hanya berubah kalau field `enabled` benar-benar dikirim.
9. **server.js** (`GET /s/:token/download`): masih memakai `res.download(path.join(storageDir, remote_file_id))`, sisa desain waktu file disimpan lokal. Semua file sekarang ada di provider remote, jadi link share selalu gagal `ENOENT` (stack trace-nya bahkan ikut terkirim ke response). Sekarang dialirkan lewat `sendRemoteFile` supaya provider dan dekripsi ikut diproses.
10. **server.js** (`GET /cdn/:slug`): tidak mengecek `expires_at`, jadi link CDN tetap melayani file yang masa simpannya sudah habis. Sekarang ikut memfilter `expires_at`.
11. **server.js** (`readProviderCapacity` Mega): membaca `storage.usedSpace` dan `storage.capacity` yang tidak ada di megajs 1.3.10, jadi pemakaian Mega selalu tampil 0 dan kapasitasnya kosong. Sekarang memakai `getAccountInfo()` -> `spaceUsed` / `spaceTotal`.
12. **server.js** (`sendRemoteFile`): jalur download Mega belum ada (`throw new Error('Download Mega belum tersedia.')`), jadi preview/download/share file Mega selalu gagal. Sekarang Mega dialirkan lewat `node.download()`. `Content-Length` juga tidak lagi dikirim supaya respons memakai chunked transfer dan tidak menggantung.
13. **server.js** (`POST /api/files`): Telegram Bot API menolak file di atas 50 MB, tetapi penolakan itu baru muncul setelah seluruh file terkirim. Sekarang ditolak lebih awal dengan status 409 dan pesan yang jelas.

Sekarang alurnya seperti Google Drive: hapus = soft delete (`deleted_at`) ke **Sampah**, dengan `GET /api/trash`, `POST /api/files/:id/restore`, `POST /api/folders/:id/restore`, `DELETE /api/files/:id/permanent`, `DELETE /api/folders/:id/permanent`, dan `DELETE /api/trash` (kosongkan). Folder yang dihapus membawa seluruh isinya, dan hanya isi yang terhapus bersamaan yang ikut dipulihkan. `PATCH /api/files/:id` dan `PATCH /api/folders/:id` sekarang melayani rename sekaligus pindah (`GET /api/folders` menyediakan daftar datar + `depth` untuk pemilih folder tujuan; pindah ke diri sendiri atau ke turunannya ditolak 400), plus toggle CDN per file. 20. **deploy.sh + redeploy.sh + update-code.sh** (update di VPS): `setup.sh` menyuntik `STORAGE_CONFIG_KEY` asli ke `ecosystem.config.cjs` yang dilacak Git, sehingga `git pull` di VPS ditolak (`error: Your local changes to the following files would be overwritten by merge: ecosystem.config.cjs`) — deploy pertama setelah setup selalu macet dan berakhir dengan edit manual. Kalau `git merge --ff-only` gagal (misalnya VPS punya commit lokal), `update-code.sh` berhenti dengan error tanpa mengubah kode, tetapi `ecosystem.config.cjs` tetap disuntik secret yang benar.

Keduanya diuji dengan `pm2`/`npm`/`curl` tiruan: happy path, gagal merge, dan aplikasi tidak merespons.
22. **server.js** (proses mati karena promise tanpa catch): megajs membuat promise internal yang reject tanpa `catch` saat akun Mega diblokir (`Error: EBLOCKED (-16): User blocked`). Node 20 mematikan proses pada unhandled rejection, jadi PM2 me-restart aplikasi berulang kali (kolom `↺` di `pm2 status` terus naik) — efeknya situs dan halaman **Owner control** terlihat rusak, padahal aplikasinya hanya crash loop. Sekarang `process.on('unhandledRejection')` dan `process.on('uncaughtException')` mencatat error dengan awalan `[unhandledRejection] aplikasi tetap berjalan:` dan **membiarkan proses hidup**. Diuji dengan `PORT=3999 node --input-type=module -e "await import('./server.js'); ... Promise.reject(...)"`: sebelum perbaikan proses keluar dengan exit 1, sesudahnya exit 0 dan pesannya tercatat. Diuji juga end-to-end lewat HTTP dengan provider Mega aktif berkredensial salah (megajs melempar `ENOENT (-9) ... Wrong password?` dan `ESID (-15) ... relogin` tanpa `catch`): log menampilkan `[unhandledRejection] aplikasi tetap berjalan: ...` dan proses tetap melayani `/api/dashboard` serta `/api/admin/overview`.
